# ROV 声光在线融合链路规格

> 版本：1.0
> 日期：2026-08-24
> 状态：已确认基线
> 上位规格：[ROV 竞赛在线系统需求规格](./rov-competition-online-system-requirements.md)

## 1. 目的与原则

本文定义 AI-D、SV1213 和 BlueROV2 状态从在线接入到 HMI 输出的完整算法契约。主链是目标/
航迹级声光融合；局部稠密双目深度是可门禁的增强分支。

设计原则：

- 最新有效信息优先于完整处理每一帧；
- 单模态退化不能无条件拖垮其他模态；
- 时间、坐标、标定和数据质量先于算法调参；
- 不确定性、来源、数据年龄和健康状态必须随结果传播；
- 在线稳定性和驾驶价值优先于完整全局 SLAM。

## 2. 在线数据流

```text
AI-D Adapter ──→ 双目校验/校正 ──→ 视觉检测、跟踪、局部深度 ─┐
                                                               ├→ 跨模态关联
SV1213 Adapter → 声呐帧校验 ─────→ CFAR/聚类/目标量测 ───────┤
                                                               ├→ 统一目标航迹
BlueROV Adapter → 姿态/角速度/深度 → 状态插值与运动补偿 ──────┘
                                                                    ↓
                                               方位、距离、类别、置信度、
                                               路径偏差、数据年龄、健康
                                                                    ↓
                                                                   HMI
```

`FUS-ARCH-001` Adapter、调度、前端、关联、跟踪、局部深度和发布必须能够独立测试和替换。

`FUS-ARCH-002` 厂商 SDK 类型只允许出现在 Adapter。核心层不得订阅厂商消息或读取厂商配置
文件作为隐式全局状态。

`FUS-ARCH-003` HoloOcean 和实机必须从规范消息入口之后共用同一条算法链。

## 3. 输入契约

### 3.1 通用头字段

`FUS-IN-001` 每条输入必须包含：传感器 ID、传感器坐标系、采集时间、接收时间、时钟域、
单调序号、观测 ID 和标定版本。

`FUS-IN-002` 观测 ID 只表示观测身份，不表示跨传感器同步关系。核心层不得通过字符串相等
把声呐帧绑定到相机关键帧。

`FUS-IN-003` capture time 用于同步和数据年龄；receive time 用于传输/排队诊断。处于不同
时钟域的时间不得直接相减。

### 3.2 AI-D 双目输入

`FUS-CAM-001` 左右图必须包含同一双目对标识、各自采集时间、宽高、步长、编码、内参、畸变
模型和外参引用。

`FUS-CAM-002` 左右采集时差不得超过 2 ms。超限、缺一目、尺寸/编码不一致或标定不匹配时，
不得运行双目深度；允许在明确单目状态下继续目标检测。

`FUS-CAM-003` 原始图、校正图和派生标定必须使用不同坐标系或明确标识，不得把 raw 图像与
rectified 内参混用。

### 3.3 SV1213 输入

`FUS-SON-001` 每帧声呐必须包含或引用：方位波束数、距离 bin 数、方位角、水平/垂直视场、
最小/最大距离、距离分辨率、工作频率、增益、名义声速和强度编码。

`FUS-SON-002` 强度数组大小必须与维度一致，量程必须单调有效，所有用于几何计算的数值必须
有限。失败帧必须计入健康，不得进入 CFAR 或关联。

### 3.4 BlueROV2 状态输入

`FUS-STATE-001` 状态至少包含姿态、角速度和深度，并携带协方差或质量标记。

`FUS-STATE-002` 姿态/深度用于采集时刻运动补偿和 HMI，不得在缺少质量标记时伪装成高可信
全局位姿。

## 4. 标定与时间模型

`FUS-CAL-001` rig 必须包含 `base_link` 到左右相机、声呐和状态参考坐标系的完整可达变换。
占位外参不得进入实机验收。

`FUS-CAL-002` 标定快照必须包含每个传感器的时间偏移、版本和生成依据。所有零偏移必须是
测量结果，而不是缺省假设。

`FUS-CAL-003` 在线运行期间标定版本变化必须触发缓存清空和融合状态重置；不得在同一航迹中
混用不同几何标定。

`FUS-SYNC-001` 每个声呐帧必须在校正后的 capture time 上选择最近的有效双目对，而不是按
输入到达顺序或观测 ID 选择。

`FUS-SYNC-002` 标称工况下，校正后的声呐—双目时间差不得超过 50 ms。超限时必须拒绝跨模态
关联，但允许两个单模态分支继续运行。

`FUS-SYNC-003` 关联计算必须把姿态/角速度插值到各传感器采集时刻。状态样本不足、过期或
插值跨越异常时，必须拒绝运动补偿后的正常融合输出。

`FUS-SYNC-004` 同步统计必须至少包含候选数、接受数、无对应帧数、超窗数、无效时间戳数、
时间差 P50/P95/P99 和最大值。

## 5. 有界缓存与调度

`FUS-Q-001` 每条输入和处理通道必须配置固定容量、最大驻留时间和溢出策略；生产配置不得使用
无界 `deque` 或等价容器。

`FUS-Q-002` 相机、声呐、局部深度和 HMI 结果通道过载时必须丢旧保新。被丢弃消息的数量、
年龄和原因必须可观测。

`FUS-Q-003` 姿态/深度通道不得静默丢失。容量不足时必须触发显式背压、合并策略或降级状态。

`FUS-Q-004` 队列中最老消息年龄不得超过该通道的数据年龄预算；超过预算的消息必须在昂贵
算法处理前丢弃。

`FUS-Q-005` 定位/状态、目标融合、HMI 发布和诊断记录必须按优先级调度；局部稠密深度和地图
不得抢占健康与最新目标结果。

## 6. 单模态前端

### 6.1 视觉前端

`FUS-VIS-001` 视觉前端必须输出目标检测或航迹候选，包括类别、像素区域、方位、置信度、
采集时间和质量指标。

`FUS-VIS-002` 双目深度必须对纹理、唯一性、左右一致性、视差范围、遮挡和标定状态执行门禁。
无效深度不得以零值或无限高置信度进入融合。

`FUS-VIS-003` 视觉前端在浑浊、弱光或单目缺失时必须报告明确退化原因，并允许单目检测继续。

### 6.2 声呐前端

`FUS-AC-001` 声呐前端必须输出一个或多个目标量测，而不是只保留整帧最高置信目标。每个量测
至少包含距离、方位、强度/置信度、尺寸或簇范围、协方差和来源帧。

`FUS-AC-002` CFAR、聚类、增益和噪声参数必须来自版本化配置；不得只依赖编译期默认值。

`FUS-AC-003` 声呐前端必须监控背景噪声、虚警密度、有效量测数、处理延迟和配置一致性，并
在输入分布明显越界时进入可观测退化状态。

## 7. 跨模态关联与航迹融合

`FUS-ASSOC-001` 关联必须同时使用时间、外参投影、方位/距离门限、类别兼容性、运动连续性和
不确定性；不得仅使用当前位姿反投影后最近邻作为唯一依据。

`FUS-ASSOC-002` 关联器必须支持一帧中的多个声呐和视觉候选，并处理未匹配、新生、合并、
分裂和消失航迹。

`FUS-ASSOC-003` 每次接受或拒绝关联必须产生可诊断原因码和门限值。门限来自配置并写入运行
清单。

`FUS-TRACK-001` 统一目标航迹必须至少包含：

- 稳定航迹 ID；
- 目标类别及类别置信度；
- 相对方位、距离及协方差；
- 首次/最后采集时间和最后发布时间；
- 视觉、声呐或声光联合来源标记；
- 当前生命周期与健康状态；
- 支撑观测 ID 列表。

`FUS-TRACK-002` 声呐负责远距离发现和距离约束，视觉负责类别和精细方位；任何一个来源缺失
时必须扩大不确定性并保留来源标记，不得伪装成完整声光结果。

`FUS-TRACK-003` 航迹超过 500 ms 未获得有效更新时必须进入过期状态并退出正常引导。删除或
保留历史航迹的策略不得改变这一 HMI 行为。

## 8. 局部稠密增强

`FUS-DENSE-001` 局部稠密深度只在双目同步、标定、纹理、视差和数据年龄全部通过门禁时运行。

`FUS-DENSE-002` 声呐弧或距离约束可以细化目标区域和结构边界，但输出必须保留视觉与声呐
原始观测的完整来源。

`FUS-DENSE-003` 局部稠密分支失败、超时或被调度器跳过时，不得阻塞目标航迹、状态、健康或
HMI 发布。

`FUS-DENSE-004` 局部深度只有证明改善结构距离、路径偏差或任务成功率时，才可以在比赛主链
中默认启用。

## 9. 输出与 HMI 契约

`FUS-OUT-001` HMI 输出必须包含目标/结构航迹、路径横向偏差、结果来源、置信度、数据年龄、
当前传感器状态和系统降级原因。

`FUS-OUT-002` HMI 发布器必须按最新状态覆盖旧状态；不得为了保证每条结果送达而显示积压
结果。

`FUS-OUT-003` 正常、降级、过期和不可用必须使用离散状态表达，不能只依靠置信度数值让驾驶
员自行推断。

`FUS-OUT-004` 原始驾驶视频与算法叠加必须解耦。算法叠加丢失时，原始视频和 BlueROV2 控制
仍必须可用。

## 10. 健康与恢复

| 故障 | 必须行为 |
|---|---|
| 视觉退化或断流 | 保留声呐搜索、粗方位和测距；视觉结果标为不可用 |
| 声呐退化或断流 | 保留近距离视觉识别和通过门禁的双目测距 |
| 双目深度失败 | 保留单目检测与声呐距离，不发布伪深度 |
| 姿态/深度过期 | 停止正常运动补偿融合，结果降为不可信 |
| 全主分支失败 | 退出算法引导，保留独立视频纯遥操作 |

`FUS-HEALTH-001` 单传感器连续缺失 3 个预期周期后必须进入降级；输入恢复后软件链必须在
2 秒内重新消费。

`FUS-HEALTH-002` 恢复时不得直接复用故障前的过期缓存。同步缓存必须清理，航迹必须经过重新
确认或明确的恢复状态。

`FUS-HEALTH-003` 健康报告必须记录最近有效采集时间、接收时间、处理时间、丢帧、队列深度、
过期数、同步拒绝数和最近错误原因。

## 11. 实时指标

`FUS-RT-001` 最低放行、标称和过载输入负载以系统上位规格为准。

`FUS-RT-002` 融合结果从采集到 HMI 可见的数据年龄 P95：标称目标 250 ms，最低放行 350 ms，
硬过期上限 500 ms。

`FUS-RT-003` 目标/路径结果最低更新率为 5 Hz，标称为 10 Hz 或新有效观测触发。重复发布旧
状态不能计入有效更新率。

`FUS-RT-004` 标称截止期违约率不得超过 1%，目标不超过 0.1%；过载测试不得超过 5%，且必须
通过丢旧保新阻止数据年龄持续上升。

## 12. 测试与验收

### 12.1 组件测试

- Adapter 字段、编码、时间戳和标定版本校验；
- 左右相机缺帧、错配、超 2 ms 和 raw/rectified 混用拒绝；
- 异步 15/5/20 Hz 与 20/10/50 Hz 组合下的最近时刻匹配；
- 声呐—相机 50 ms 边界、时钟偏移校正和状态插值；
- 多目标关联、航迹生命周期、来源和协方差传播；
- 各队列溢出、丢旧、过期、背压和统计；
- 单模态退化、恢复和缓存清理。

### 12.2 在线集成测试

`FUS-ACC-001` HoloOcean 标称运行必须产生非零声呐检测、视觉检测、统一航迹和可见条件下的
声光联合航迹；只证明进程运行不构成通过。

`FUS-ACC-002` 在线报告必须包含数据年龄 P50/P95/P99、各阶段耗时、截止期违约率、队列深度、
丢弃、同步、关联、航迹、健康转换和资源占用。

`FUS-ACC-003` 必须完成 2 小时标称稳定性测试和 30 分钟过载/故障测试，并满足上位规格的
资源、恢复和任务指标。

`FUS-ACC-004` MCAP 回放可以用于重现失败输入，但不得替代在线队列、调度、HMI 和恢复验收。
