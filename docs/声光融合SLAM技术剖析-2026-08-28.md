# 声光融合 SLAM 技术剖析：从因子图优化到实时目标跟踪

> 结合 `uw_slam` 仓库的实际实现，讲清楚两条主线各自用了什么 SLAM/估计理论、
> 为什么这么选、代码里具体怎么落地。面向已经了解 SLAM 基本概念的读者；
> 术语不做通俗化改写，但每一处理论选择都会落回具体源码文件和函数名。

## 引言：水下定位为什么是一个"状态估计"问题

水下机器人没有 GPS——电磁波在水里传播几米就衰减殆尽。它能拿到的只是一串
带噪声的局部观测：这一步相机看到画面挪动了多少、那一下声呐测到某个方向多远、
深度计读到多深。SLAM 要回答的问题是：**给定这一整串有噪声的观测，最可能的
真实轨迹和环境地图是什么？**

这本质上是一个统计推断问题。把机器人在各个时刻的位姿记作待求的随机变量
`x_0, x_1, ..., x_n`，把传感器观测记作 `z_1, ..., z_m`，在高斯噪声假设下，
求"给定观测 z，最可能的状态 x"（最大后验估计，MAP）等价于求一个加权最小二乘
问题：把每条观测的负对数似然（在高斯假设下就是一个二次型）加起来，找一组状态
让这个总和最小。这套推导是几乎所有现代 SLAM 系统的理论基础，也是本文要讲的
两条主线共同的出发点——区别只在于**用什么方式去逼近这个最优解，以及愿意为
"更优"付出多大的实时性代价**。这正是本文的主线：主线一（离线管线）选择了
"攒够数据、一次性批量求解"的因子图优化路线，逼近真正的 MAP 最优解；主线二
（实时闭环）选择了"来一条处理一条"的滤波/跟踪路线，牺牲全局最优性换取有界延迟。
下面分别展开。

---

## 一、主线一：批量因子图 SLAM——如何把"一堆传感器读数"变成"一条最优轨迹"

### 1.1 状态表示的取舍：为什么是 7 参数而不是欧拉角、也不是完整李代数

`include/sensor_models/geometry.hpp` 里的 `Pose3` 只有两个成员：一个三维平移
`translation` 和一个单位四元数 `rotation`，对外还提供 `ToParameterBlock()`/
`FromParameterBlock()` 把自己摊平成 7 个 `double`（`tx,ty,tz,qx,qy,qz,qw`）。
这个选择背后有两层考量：

- **不用欧拉角**：欧拉角在特定姿态组合下会丢失一个自由度（万向锁），而且插值/
  求导都要处理周期性和奇异性问题，仓库 `CLAUDE.md` 明确记录这是从 `ocean_t`
  的审计教训里改掉的模式。四元数没有奇异点，代价是 4 个数表示 3 个自由度、
  存在一个多余的约束（单位模长）。
- **也不是完整的 SE(3) 李代数库**：头文件注释直言"不是 Sophus/manif 那种
  完整的李代数库，只够用来做 compose/inverse/apply"。这意味着优化时不是在
  正规的切空间（tangent space，6 维 `[dt, dtheta]`）上做最小更新，而是直接对
  7 个参数做欧氏空间的加法更新，每步之后再把四元数部分重新归一化
  （`estimation/gauss_newton_solver.cpp` 的 `RenormalizeQuaternion`）——这是一个
  **明确标注的 v1 简化**：正确性够用（四元数的过参数化在小步长下不会带来严重的
  数值病态），但比起真正的流形优化（在正规的旋转群上做更新）theoretically 不够
  优雅。换成 Ceres/GTSAM 之后，这里可以升级成 `LocalParameterization`/流形更新。

### 1.2 感知前端：把物理信号变成"证据"——三种不同的推断问题

#### 1.2.1 声呐：一个假设检验问题

成像声呐每个像素给出的是回波强度，要从中判断"这是目标还是背景噪声"，这在信号
处理理论里是经典的**二元假设检验**问题：H0（只有背景噪声）vs H1（目标 + 噪声）。
如果直接设一个固定强度门限，海况变化、多径混响会让门限要么漏检要么虚警爆炸——
这正是 **CFAR**（恒虚警率检测）要解决的问题：让检测门限随局部背景噪声水平自适应
浮动，同时把误报概率（Pfa）控制在一个预先设定的常数上。

`src/frontends/cfar_detector.cpp` 里能直接看到这套理论如何落地成代码。以最基础
的 CA-CFAR（Cell-Averaging）为例：

```
threshold_factor_ca_ = ntc * (pow(pfa, -1.0 / ntc) - 1.0);
```

这正是在背景服从指数分布（声呐强度平方律检波后的典型噪声模型）假设下，由
"训练细胞数 `N`（`ntc`）+ 目标虚警率 `Pfa`"反推检测系数 `α` 的经典闭式解：
`α = N·(Pfa^(-1/N) − 1)`。检测时用当前像素周围的训练像素（隔开若干"保护像素"，
避免真实目标本身的能量泄漏进训练窗口抬高背景估计）算出局部背景强度均值，乘上
这个 `α` 就是这个像素专属的检测门限。仓库同时实现了 SOCA/GOCA/OS 三种变体
（`CfarVariant`），分别通过"取前后训练窗口的较小/较大值"（SOCA/GOCA，用来应对
杂波边缘和相邻多目标互相掩蔽的场景）或"对训练窗口排序取第 k 大"（OS-CFAR，
对孤立强杂波更稳健）来解出各自的门限系数——本质上都是同一个 Neyman-Pearson
框架下，针对不同噪声/杂波假设换一种背景强度估计器。

检测出的候选点接下来要聚类成"目标"：`sonar_cfar_frontend.hpp` 用 DBSCAN
（`dbscan_eps_m=0.2`、`dbscan_min_samples=2`）在极坐标空间里按密度聚类，
避免同一个物体的多个回波点被误判成多个目标。这里有一处架构层面的理论纪律
值得强调：整条链路**始终停留在声呐本地极坐标系（range, bearing）**，从不转换到
笛卡尔世界坐标（这是相对 `sonar_camera_reconstruction` 原版移植时刻意舍弃的一步，
见 `NOTICE`）。理由是测量模型的可观测性：成像声呐物理上只能约束"距离"和"方位角"
两个维度，**不能观测仰俯角**（elevation）。如果前端自己编一个仰俯角把点摆到笛卡尔
空间里，等于用不存在的信息伪造了一次观测——这正是下面因子构建阶段"声呐距离因子
不能凭空给出 z 信息"的根源。

#### 1.2.2 双目视觉：对极几何 + 刚体配准的经典流水线

`include/frontends/stereo_landmark_vo_frontend.hpp` 的 `StereoLandmarkVoFrontend`
实现的是教科书式的稀疏特征点视觉里程计（VO）流水线，每一步都能对应到一个具体的
几何/统计问题：

1. **特征检测**：`kBrightBlob`（合成场景的高亮方块，配合按 id 唯一的哈希纹理）
   或 `kHarrisCorner`——后者是经典的 Harris 角点响应，本质是用图像局部灰度梯度
   构造的二阶矩结构张量，通过其两个特征值判断该点在各个方向上灰度变化是否都
   足够剧烈（真正的"角点"而非边缘或平坦区域）。
2. **立体匹配 + 三角化**：左右图之间用 `PatchMatcher`（NCC，归一化互相关）在
   极线约束下找对应点，视差换算深度——立体视觉的基本关系式是
   `depth = focal_length × baseline / disparity`，这也是为什么代码里
   `min_disparity_px` 要设一个下限（视差趋近 0 时深度趋于无穷，数值上不可用）。
3. **时序匹配**：当前帧路标和上一帧路标再做一次 NCC 匹配，得到帧间对应点对。
4. **刚体变换求解——Kabsch/Procrustes 算法**：`src/frontends/rigid_transform_fit.cpp`
   给定两组配对好的 3D 点集 `{a_i}`、`{b_i}`，求一个刚体变换（旋转 R + 平移 t）
   最小化 `Σ‖b_i − (R·a_i + t)‖²`。闭式解是：先各自减去质心得到中心化点集，构造
   `H = Σ (a_i − centroid_a)(b_i − centroid_b)ᵀ`，对 `H` 做 SVD 得 `H = U·S·Vᵀ`，
   则 `R = V·Uᵀ`（若 `det(R) < 0` 说明结果是反射而非旋转，需要翻转 `V` 的最后一列
   再重算，代码里用一个对角为 `[1,1,-1]` 的修正矩阵完成这一步），平移
   `t = centroid_b − R·centroid_a`——这正是 Kabsch (1976) / Umeyama (1991) 算法的
   标准形式，代码注释直接引用了这两篇经典文献。
5. **RANSAC 鲁棒化**：真实匹配里混有错误对应（外观相似但物理上不是同一点），
   直接对全部点做 Kabsch 会被外点带偏。`FitRigidTransformRansac` 反复从匹配集里
   随机抽 3 点闭式求解、用误差阈值 `inlier_threshold_m` 统计有多少点支持这个假设、
   保留支持者最多的一组，最后**只对这组内点**重新做一次完整 Kabsch 求精——这是
   标准 RANSAC 的两阶段结构（假设生成 + 一致性评分 + 内点集精炼）。
6. **协方差估计**：拟合完成后，代码没有像很多简化实现那样给一个固定的置信度，
   而是对内点残差做数值雅可比、算出正规方程 `JᵀJ` 的条件数（`normal_matrix_
   condition_number`）——条件数过大说明内点的空间分布退化（比如接近共线/共面，
   这种几何配置下某些运动方向"看不清楚"，解会对噪声异常敏感），此时宁可整体
   拒绝这次拟合也不要报一个虚假的低不确定度；同时残差方差有一个下限
   （`residual_variance_floor_m2`），避免极少数点凑巧拟合得"过分完美"时报出
   不合理的零不确定度。这个协方差最终会被白化进下面的相对位姿因子里，让优化器
   知道"这次 VO 结果有多可信"。

真实场景下这条流水线也有已知的失效边界：真实机体非纯 y 轴基线的标定会让双目
校正后的主点大幅偏移，Harris 角点在这种画面上的匹配质量明显下降（见 README
「已知边界」一节，ATE 停在 4.3 米、求解器不收敛）——这不是这套理论本身的问题，
而是"合成数据下验证过的检测器参数，没有覆盖真实标定引入的几何畸变"这一具体
工程边界。

#### 1.2.3 声光跨模态关联：一次跨传感器的贝叶斯融合

成像声呐只能给出"距离 + 方位角"，物理上等价于说目标位于一段以声呐为顶点、
张角为声呐仰俯孔径的**圆弧**上（`sensor_models/sonar_arc_projector.hpp` 里的
参数方程 `p(φ) = ρ·[cosφ·cosθ, cosφ·sinθ, sinφ]`，`φ` 在孔径范围内采样）。
如果目标恰好也落在相机视野里，就可以把这段弧投影到图像上、看它是否穿过相机
检测到的目标区域——这在几何上是用"另一路独立观测"去打破声呐单次测量的仰俯角
不确定性，本质就是多传感器融合里最基础的一种操作：**用一个更强约束的观测，
收窄一个欠约束观测的解空间**。

真正把这次几何关联落成一个数值上的深度估计，是 `posterior_depth_optimizer.hpp`
的 `OptimizePosteriorDepth`。它的目标函数是一个教科书式的三项加权最小二乘（等价于
三个独立高斯似然相乘后取负对数）：

```
min_d  (d − d_o)² / σ_d²  +  (range(d) − ρ)² / σ_ρ²  +  (bearing(d) − θ)² / σ_θ²
```

第一项是光学先验深度（来自相机/立体匹配）的似然，后两项是把候选深度 `d` 反投影
回声呐坐标系、和声呐实测的 range/bearing 比较的似然（`UnprojectPixelToSonarRangeBearing`
做这个反投影）。三项各自的方差 `σ²` 就是各自传感器的置信度权重——这正是贝叶斯
融合"按不确定度加权"的直接体现。v1 版本用简单的高斯代价（没有上稳健核），求解
方式也刻意保守：不是无约束高斯牛顿（可能在非单峰目标函数上发散），而是在
`[d_o − k·σ_d, d_o + k·σ_d]` 区间内做**黄金分割搜索**（golden-section search，一种
不需要梯度、保证收敛于单峰区间内极值的确定性搜索算法），代价是假设了目标函数在
这个窗口内基本单峰。得到的后验方差用 **Laplace 近似**给出——在极值点附近对目标
函数做二阶展开，用二阶导数的倒数（`2 / f''(d*)`，中心差分数值计算）近似后验分布
的方差，这是把一个非高斯后验用一个高斯去近似的标准手段。

而这次融合结果的判定环节也有一处不那么直觉的统计设计：`AcousticOpticAssociator`
在候选声呐弧采样点离相机检测目标的评分接近时，并不会立刻判"存在歧义"——因为
在声呐正前方（boresight）附近，仰俯角对方位角和距离的几何影响本身就很弱，同一
段弧上采样出的多个候选点打分天然接近，这是测量模型本身的性质，不是关联出了
问题。只有当这些候选的**深度值**本身也不能在联合方差门（`depth_agreement_sigma`
倍标准差）内达成一致时，才真正判定为 `AMBIGUOUS`——这是把"打分接近"和
"物理上确实存在多个可能解"两件事分开判断，避免了一种常见的误判：把测量模型的
固有几何弱观测性错当成数据关联失败。

### 1.3 因子图构建：从"观测"到"残差"

前端产出的每一条证据，最终要变成因子图里的一个**因子**——一个把"当前猜测的
状态"映射到"和这条观测差多少"的函数，这个差值叫**残差**（residual）。在高斯
噪声假设下，MAP 估计问题就等价于最小化所有残差的加权平方和，而"加权"具体是
用每条观测协方差的逆矩阵的平方根（**信息矩阵的平方根**，即白化矩阵）去乘残差，
让不同置信度的观测在同一个数值尺度上参与竞争——这正是 `factor_builders/` 目录
每个 `*_residual.hpp` 都在做的事。三类主要因子及其精确形式：

- **相对位姿因子**（`relative_pose_residual.hpp`）：6 维残差，平移部分是
  `Rᵢᵀ(tⱼ − tᵢ) − measured_translation`（把猜测的位移变换到前一帧自己的参考系
  下再和实测比较），旋转部分是 `2·vec(measured_qᵀ · (qᵢᵀ · qⱼ))`——这是四元数
  误差在小角度近似下的标准形式（VIO/SLAM 文献里的常见写法）。雅可比这里没有用
  解析形式，而是对两个参数块做内部中心差分数值微分——代价是每次残差求值要多算
  24 次（6 维残差 × 2 个参数块 × 双侧差分），换来的是"正确性由构造保证"，不用
  手推容易出错的四元数导数；文档里明确说这是换 Ceres/GTSAM 之后该升级成解析
  雅可比的地方。
- **声呐距离因子**（`sonar_range_residual.hpp`）：1 维残差
  `measured_range − ‖pose.translation − mean(landmark_subset_W)‖`。这条因子背后
  有一个重要的架构决策：v1 的因子图**只优化关键帧位姿，不把路标点也当成联合优化
  的变量**（这是平台架构文档明确记录的延后决策），路标位置来自
  `SubmapManager::QueryNearestPoint`——用当前死推算位姿把这次声呐检测投到世界系、
  在 1.5 米门限内找最近的已知路标，命中就复用、未命中就新建。这本质上是把
  "同时估计位姿和地图"（完整 SLAM 问题）简化成"用一个粗糙但持续更新的地图去
  约束位姿"（有点类似位姿图 SLAM 里把路标边缘化掉、只留一元/二元位姿约束的思路，
  只是这里的"边缘化"更粗糙——直接用最近邻代替真正的高斯边缘化）。这条残差公式
  移植自 SVIn 的 `SonarError`，但雅可比是重新推导的：上游走的是"声呐波束端点方向"
  的近似路径，和这条残差公式在数学上并不严格对应，直接复用会引入系统性偏差
  （详见 `NOTICE`）。
- **深度因子**（`depth_residual.hpp`）：1 维残差
  `measured_depth_m + translation.z()`（世界系 z 朝上、深度计读数正向下，符号
  相反）。这条因子在理论上承担着一个关键角色：**打破规范自由度**（gauge
  freedom）。只有相对位姿和声呐距离约束时，整条轨迹的雅可比矩阵在"整体平移/
  旋转"这些方向上存在零空间——给所有关键帧位姿同时施加一个刚体变换，所有残差
  都不变，正规方程 `JᵀJ` 在这些方向上奇异，优化问题欠定。深度因子给 z 方向引入
  了一个绝对参照，消除了这个方向上的零空间，但 x/y/yaw 仍然是纯相对约束下的
  自由度，需要靠固定一个关键帧（`PoseGraphProblem::AddKeyframe(..., fixed=true)`）
  来锚定。这里有一个真实踩过的坑：早期版本把锚点关键帧的 z 也想当然地钉在 0，
  而其它关键帧同时被真实深度证据往非零方向拉，两者在优化的意义上互相矛盾（正规
  方程条件数极差），求解器 30 轮不收敛、最终误差 4.6 米——后来把锚点的 z 也设成
  它自己的真实深度证据才解决，这是一次教科书式的"约束之间数值上不自洽"案例，且
  只有跑一遍真实的端到端 demo 才暴露出来，单元测试测不到这种全局约束层面的病态。
- **回环闭合因子**：结构上和相对位姿因子相同，只是关联方式不同——不是相邻帧
  之间，而是通过位姿邻近检索找到"可能是同一地点"的历史关键帧候选，再用当前帧
  的立体三角化点云和候选帧重新做一次刚体拟合（RANSAC）验证，成功则补一条跨越
  长时间的强约束边。这类边天然更可能包含误匹配，所以进图时会挂上
  `RobustPolicy::kHuber`（下一节展开）。v1 的候选检索完全基于死推算坐标的欧氏
  距离，**没有**做外观层面的回环检测（比如 DBoW2 那类视觉词袋检索），这是刻意
  记录在案的功能边界，不是缺陷。

### 1.4 非线性最小二乘求解：Levenberg-Marquardt 的具体实现

因子图搭好后就是标准的非线性最小二乘问题：`min_x Σ ‖rᵢ(x)‖²`。`estimation/
gauss_newton_solver.cpp` 的 `GaussNewtonSolver::Solve` 是一个手写的、教科书式的
LM 实现，值得逐步拆解：

1. **正规方程**：每轮迭代先在当前线性化点求出雅可比 `J` 和残差 `r`，累加
   `JᵀJ`（近似 Hessian）和 `Jᵀr`（梯度）——`EvaluateAll` 遍历每个残差块，把它对
   涉及的每个自由关键帧的雅可比累加进 `jtj`/`jtr` 对应的分块位置（固定关键帧
   没有对应列，直接跳过，这就是锚点"不参与优化"在代码里的样子）。
2. **阻尼与信赖域**：纯 Gauss-Newton 的更新方向是解 `JᵀJ·Δ = −Jᵀr`，但在
   `JᵀJ` 病态或非凸区域，这一步可能"迈过头"甚至发散。LM 在对角线上加阻尼：
   `(JᵀJ + λ·diag(JᵀJ)) · Δ = −Jᵀr`——`λ` 越大，这一步越接近"沿负梯度方向走一小步"
   的梯度下降（保守但稳），`λ` 越小越接近纯 Gauss-Newton（激进但可能发散）。代码
   里每次试探性地施加这个阻尼求解、应用增量、重新算一次代价：如果代价确实下降了
   就接受这一步、把 `λ` 除以 `lambda_down_factor`（下次敢迈更大步子）；如果反而
   变差就回滚参数、把 `λ` 乘以 `lambda_up_factor`（更保守），最多重试
   `max_inner_retries` 次——这正是 LM 算法里"自适应信赖域半径"思想的直接实现。
3. **稳健核（Huber）的 IRLS 实现**：只有挂了 `RobustPolicy::kHuber` 的残差块
   （目前只有回环边）会在残差范数超过 `huber_delta` 时，把残差和对应的雅可比
   同时乘上一个缩放因子 `w = √(huber_delta / ‖r‖)`。这是 **IRLS**（迭代重加权
   最小二乘）风格的 Huber 实现：把稳健代价函数的效果，转化成对当前残差做一次
   幅度压缩，这样后续所有累加逻辑（代价、`JᵀJ`、`Jᵀr`）都不需要区分"这是不是
   稳健因子"，直接读取已经缩放过的值即可。代码注释里特别说明这是 Ceres 内部
   `Corrector` 的简化版——少了二阶曲率修正项，因为纯 Gauss-Newton 求解器本来就
   不利用二阶曲率信息，加了也没有意义。
4. **收敛判据**：不是看代价绝对下降了多少，而是"代价变化 < 容差 × max(1, |代价|)"
   ——即相对量而非绝对量。这里也有一段真实踩过的坑：容差如果设成绝对值 `1e-12`，
   在几十到几百量级的代价规模下会正好卡在 `EvaluateAll`/LDLT 分解的浮点噪声地板
   附近，导致一个已经收敛到 12 位以上有效数字的问题，是报 `converged` 还是
   `stalled`，实际上取决于"数值噪声先跨过阈值"还是"真实代价变化先跨过阈值"这两个
   本该无关的事件谁先发生——同一个问题换一次噪声实现（`synth_bag_gen` 的 RNG
   拆流）就能把结果从收敛翻转成不收敛。修法是把容差换算成相对值，默认值也从
   `1e-12` 调宽到 `1e-9`，离浮点噪声地板留出安全边际。

这整套实现刻意停留在稠密 `O(n²)` 线性代数（`Eigen::MatrixXd` 稠密求逆），
对应架构文档第 20 节"第一版图优化库、要不要换 Ceres/GTSAM 是延后到有实测基准
数据后再定的决策"——`estimation`/`mapping` 层对外只暴露纯虚接口
（`Solver`、`SurfelSpatialIndex`），Ceres 版本的 `ceres_v1` 已经作为可切换后端
实现好、等 `tools/bench/solver_benchmark.sh` 的数据说话。

### 1.5 地图管理：为什么地图证据要存在局部坐标系里

`mapping/submap_manager.hpp` 的 `SubmapManager` 有一条从架构层面看很关键的设计：
每份地图证据（点云）永远以它所属关键帧的**局部坐标**存储，从不在插入那一刻就
烘焙成固定的世界坐标。查询世界坐标（`WorldPointsForKeyframe`）时才用这个关键帧
**当前**的位姿现算一遍。这样设计的本质是让地图管理和"位姿会被后续优化修正"这件
事解耦——图优化每次重新线性化都可能微调历史关键帧的位姿（尤其是回环闭合触发
之后），如果地图点在第一次观测时就固化成世界坐标，位姿一修正地图就跟着"撕裂"；
延迟到查询时才变换，位姿修正会自动、无感地传播到地图上，不需要重新跑一遍前端、
也不需要谁手动去"修复"已经存好的点云。这是增量式/批量式 SLAM 系统里地图管理的
标准做法（对应 g2o/GTSAM 生态里"位姿变了，依赖它的一切都要能重新算出正确值"的
一般原则），也是这里刻意规避 `sonar_camera_reconstruction` 原版"进来就烘焙进
世界系"做法的原因（见 `NOTICE`）。

## 二、主线二：实时目标跟踪——为什么这里不是因子图，而是一个轻量滤波器

### 2.1 从"批处理最优"到"有界延迟"：实时系统对估计理论的重新取舍

主线一的因子图优化是**批处理**的：攒够一批观测，一次性对所有历史状态重新
线性化求解，计算量随关键帧数增长（稠密实现下是 `O(n³)`）。这在追求精度、
不在乎处理时长的离线分析场景里没问题，但对着一个正在水下遥控的 ROV 实时算，
这套代价结构是灾难——处理时间会随着任务时长无界增长，而操作员等不起。

主线二因此换了一套完全不同的估计范式：`OnlineAssistPipeline` 用的不是因子图
批量优化，而是经典的**逐步预测-更新滤波/多目标跟踪（MTT）**思路——每来一条
新观测，只更新受它影响的那一个目标航迹的状态，计算量是 `O(1)` 增量，不随历史
长度增长。这是一次实时性对最优性的**主动让步**：换来的是有界延迟和内存占用，
代价是放弃了"重新审视全部历史观测、找全局最优解"的能力——一旦某次关联判断错了，
不会像因子图那样在后续优化里被别的证据"拉回来"。这个取舍在系统设计里是显式的、
被文档记录的，不是偷懒。

### 2.2 目标状态模型：一个恒速运动假设下的轻量滤波器

`include/frontends/target_tracker.hpp` 的 `TrackedTarget` 给每个目标维护一个
4 维状态 `[bearing, ḃearing, range, ṙange]`（方位角、方位角变化率、距离、距离
变化率）和一个 4×4 协方差矩阵——这是**恒速模型**（constant velocity model）
在极坐标观测空间下的直接体现：假设短时间窗口内目标的角速度/径向速度近似恒定，
用它做运动预测（`max_prediction_dt_s` 限制了外推多久还可信，超过就不再预测、
直接标记陈旧）。这本质上是一个简化版的卡尔曼滤波结构（状态 + 协方差 + 预测/
更新循环），但比标准 EKF 更轻量：v1 没有做完整的协方差传播矩阵推导，配对判定
用的是马氏距离门控——用当前状态协方差把"新检测和预测状态的偏差"转换成一个
考虑了不确定度的统一尺度距离，越不确定的航迹允许的绝对偏差越大，这和主线一
里 `TargetAssociator` 做跨模态关联时用的是同一类统计工具。

**航迹生命周期管理**是这类多目标跟踪系统里另一个经典问题——如何决定一条候选
航迹"够不够格"被相信、什么时候该被放弃：

- 连续命中 `confirm_hits`（默认 2）次才从"待确认"升级为"确认"，避免一次孤立的
  误检测（一次 CFAR 虚警、一次视觉噪声）冒充成正式目标；
- 连续 `degraded_misses`（默认 3）次没有新检测，航迹标记降级；
- `stale_after_s`（默认 0.5 秒）没更新标记陈旧，不再用于指导操作员，但仍保留
  在内存里；
- 只有到 `retention_after_s`（默认 5 秒，刻意比"陈旧"宽松很多）才真正从内存里
  清除——这是为了让短暂被遮挡后重新出现的目标能接续原有编号，而不是每次都算
  一个新目标、编号无限增长；仓库文档记录过这条策略是为了修一个真实的资源问题：
  没有这条清理逻辑的话，从未确认的孤立虚警会一直占着内存、每次发布都要为它跑
  一次预测，长时间运行下内存和 CPU 都会无界增长。

这套"确认门限 + 未命中容忍 + 陈旧/清除分级"的结构，是多目标跟踪领域里
"轨迹起始-确认-终结"（track initiation/confirmation/termination）问题的一个
标准解法框架，只是这里的参数选择偏保守、偏向简单直观的计数规则，而不是更精确
但更重的序贯概率比检验（SPRT）之类的方法——同样是"实时性优先于统计最优性"这一
取舍的延续。

### 2.3 跨模态关联的实时化：从"批量对齐"到"延迟窗口配对"

主线一的声光关联是离线的：整份 bag 已经在手上，可以按需要的顺序反复处理。
主线二做不到——视觉和声呐是两条独立、异步到达的数据流，`OnlineAssistPipeline`
的设计是让两路检测各自独立运行（互不阻塞），视觉检测先缓存在 `pending_visual_`
里，等下一次声呐数据到达时一起做一次 `TargetAssociator::Associate` 关联批处理；
只有当声呐确实掉线超过 `modality_stale_after_s` 时，才改为让视觉检测立即单独
触发一次发布。这是**有限延迟窗口内的尽力配对**策略，本质上是把"异步多传感器
融合"问题简化成"以慢的那一路为节拍、在一个短窗口内凑单"，比真正的时间戳最近邻
插值/连续时间融合更简单，但代价是有一个隐含的假设：两路传感器的到达节拍差异
在这个窗口内不会造成明显的运动模糊。

稠密立体深度补全走的是另一套逻辑——它是这条流水线里唯一计算量重到需要显式
预算决策的部分（块匹配算法本身不可抢占），`DenseDepthProvider::RunBounded`
执行完之后才做事后墙钟检查，超预算的结果直接丢弃。这是一种朴素版的
**anytime computation**（可随时中断、时间越多结果越好的计算范式）工程近似：
不是让算法本身支持提前终止返回一个粗糙解，而是完整跑完、超时就整体作废——
简单但有效，因为块匹配的计算时间相对可预测，"跑完才发现超时"和"提前终止拿到
部分结果"两者的实际收益差别不大。

### 2.4 实时基础设施：背压和 deadline 感知调度

再精巧的估计算法，如果被上游数据积压拖垮也没有意义。`include/runtime/
live_event_source.hpp` 的 `LiveEventSource` 解决的是一个经典的**排队论/实时
系统调度**问题：四条车道（定位/修正/建图/证据）各自独立的容量和溢出策略——
定位车道用 `kReject`（显式背压，宁可让上游知道"处理不过来了"也不悄悄丢定位
数据）；修正/建图车道用 `kDropOldest` 并附加 `max_residence_s`（0.5 秒）的
"最长驻留时间"——一条数据在队列里等待超过这个时长后，直接在出队**之前**丢弃，
不进入处理逻辑。这个"处理前先看还有没有意义"的判断，对应的是实时系统里
**deadline 调度**的核心原则：一个已经违反了自己下游硬性延迟预算的任务，继续
花算力处理它是纯粹的浪费，不如把算力让给还有意义的新数据。这和传统操作系统
调度里的 EDF（Earliest Deadline First）思想同源，只是这里的判据更简单——不是
按剩余时间排序调度，而是按"是否已经过期"做二值取舍。

### 2.5 健康状态机：把"降级"当成一等公民而非异常分支

`ComputeDegradation` 是一个固定优先级的规则链（recovering → 双模态皆死 →
车辆状态陈旧 → 单模态死 → 前端自报降级 → 稠密超期 → 健康），本质上是一个
简单的**有限状态机**，但它的设计哲学值得单独一提：单模态传感器掉线只报
"可疑"（SUSPECT）而不是"不可用"，并且明确保证这时候给操作员的引导依然有效
（`guidance_valid=true`）。这是把"优雅降级"当成系统的**常规工作模式**而不是
异常处理分支来设计的——现实里传感器抖动/丢帧是常态，一个把"任意一路传感器
波动"就升级成"系统不可用"的设计，在真实水下环境里会频繁触发不必要的告警。

## 三、两条主线共享的底层工程逻辑

抛开各自的估计理论选择，两条主线在工程层面遵循着同一组更底层的原则，这些原则
本身也值得从"为什么这样设计"的角度看一遍：

- **纯虚接口 + 依赖注入，把"用什么算法"和"整条链路怎么编排"解耦**：
  `estimation`/`mapping` 层只依赖 `Solver`/`SurfelSpatialIndex` 这类纯虚接口，
  具体实现（`gauss_newton_v1`、`ceres_v1`、nanoflann 空间索引）在 `adapters/`
  层，由 `application` 层注入。这不是单纯的代码整洁癖好，而是让"未来把 v1 求解器
  换成 Ceres/GTSAM"这件事，理论上不需要改动因子构建/前端任何一行代码——这正是
  依赖倒置原则在一个持续演进的研究型代码库里最实际的价值：给理论选择的迭代
  留出空间，而不必推倒重来。
- **显式、单独播种、永不重播种的 RNG**：`StereoLandmarkVoFrontend` 的 RANSAC、
  `synth_bag_gen` 的各类噪声，都各自持有一条独立的、构造时播种一次、之后绝不
  重新播种的 `std::mt19937_64`。这不是随意的编码规范，而是**科学实验可重复性**
  的基本要求——如果一次算法评测（"这次改动让 ATE 变好还是变差了"）用的是全局
  共享或运行中途重播种的随机数流，实验结果的差异就无法归因：到底是算法真的变了，
  还是噪声实现意外发生了耦合？仓库自己就踩过这个坑——`synth_bag_gen` 早期三种
  互不相关的噪声共用一条 RNG 流，一次改动场景配置里的目标数量意外改变了后续所有
  keyframe 的位姿噪声抽样序列，导致两个只差目标数量的 experiment 报出几倍的 ATE
  差异，被误读成"声光融合让精度变差"——实际两者毫无因果关系。
- **fail-closed 优先于优雅地"凑一个答案"**：无论是 `SonarCfarFrontend` 的健康
  阈值、`OpenCvVisualAssistFrontend` 的质量门（亮度/对比度/清晰度/结构支撑度
  任一不达标就整体拒绝），还是 `PoseGraphProblem::AddResidualBlock` 遇到解析
  失败/身份重复直接让整场回放非零退出，这条系统里到处贯彻着同一个取舍：宁可
  明确报告"这次不可信/不可用"，也不要在内部悄悄降质、把一个不可靠的结果包装成
  正常输出交给下游——下游（无论是评测脚本还是操作员）没有能力分辨一个"看起来
  正常但实际已经跑偏"的结果。

## 四、总结：两条主线分别对应 SLAM 理论谱系上的哪个位置

用一句话概括两条主线在经典 SLAM 理论谱系里的位置：**主线一是图优化派
（graph-based SLAM）在小规模问题上的一个手写实现，用批量非线性最小二乘逼近
真正的 MAP 最优解；主线二是滤波/跟踪派（filtering-based tracking）思路的一个
轻量实现，用逐步更新换取有界延迟，主动放弃全局重新线性化的能力**。这不是
"哪种更先进"的问题——图优化和滤波在 SLAM 发展史上本就是两条并行演进的路线，
各自适配不同的实时性/精度取舍，这个仓库把两者都做出来、共用同一套感知前端和
消息模型，恰好是一个能同时看清两种范式各自代价与收益的具体案例。

当前版本在两条主线上都留有明确记录在案的简化和边界：主线一的求解器仍是手写
GN/LM 而非成熟的 Ceres/GTSAM、路标点未联合优化、回环检索没有外观层面的词袋
匹配；主线二的整条实时闭环尚未在真实 HoloOcean/UE5 仿真器上跑通过一次端到端
验证。这些边界在仓库文档（`README.md`「已知边界」、`CLAUDE.md`「已经踩过的坑」）
里都有据可查——对一个"骨架 + 每层至少一条真实可跑通路"阶段的工程框架而言，
诚实记录这些边界，本身也是这个项目工程纪律的一部分。
