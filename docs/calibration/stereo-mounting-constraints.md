# 双目相机选型与安装约束（交采购 / 结构设计）

> 任务编号：PREP-B-08 第 1 步 · 状态：v1 草案 2026-09-03 · 出自 `docs/ROV平台到货前准备工作规格-2026-09-02.md`
> 读者：采购、结构设计、电气；本文只讲"硬件必须满足什么"，不讲算法。
> 到货后的验收流程见同目录 `stereo-acceptance.md`。

## 0. 为什么要提前写死这些约束

仓库的双目视觉里程计（`stereo_landmark_vo_frontend` + 回环闭合 + 双目光学深度前端）在两次真机数据上踩过两个坑，都不是软件 bug，都出在硬件形态上：

| 教训 | 现象 | 根因 |
|---|---|---|
| (a) 基线不平行 | 真实 HoloOcean 机体录制，ATE 从 0.67 m 崩到 4.32 m，求解器 30 次迭代 `stalled` | 左右相机基线有 15–17% 的 x/z 分量（`configs/rig/example_auv_real_camera.yaml`）；`cv::stereoRectify` 为满足行对齐必须施加真实旋转，把左相机主点从 cx≈256 搬到 cx≈170（图像宽 512），角点跟踪/RANSAC 在这种图上失效 |
| (b) 细纹理被削弱 | 同一段数据，跟踪率从 50/50 掉到 8/50 | 双线性重采样（去畸变/rectify 或压缩）抹掉了水下弱纹理 |

结论：**双目上机后能不能用，在机械设计和采购阶段就已经决定了大半**。下面每条约束都对应上面某个坑或已知的软件前提。

## 1. 必须满足（不满足则双目 VO 不可用，采购前需回签）

| # | 约束 | 数值 | 对应原因 |
|---|---|---|---|
| M1 | 双目**刚性固定在机体**，不上云台 | — | VO 要求相机→机体外参恒定；云台相机（IMX462）仍只做飞手视频和目标检测 |
| M2 | 基线平行于机体横轴（y 轴，左正右负） | 基线向量的 x、z 分量各 **< 3%** 基线长度（例：10 cm 基线 → x、z 各 < 3 mm） | 教训 (a)；`StereoGeometry::Resolve` 要求近似纯 y 轴平移 |
| M3 | 两相机光轴平行且都指向机体 +x | 相对旋转 **< 0.5°**（三轴各） | 同 (a)；剩余旋转由标定吸收，但越大主点搬得越远 |
| M4 | 基线长度 | **8–12 cm**（工作距离 0.5–6 m） | <8 cm 远处深度分辨率不够；>12 cm 近处重叠视场不足且难以并入耐压舱 |
| M5 | 两路相机**同型号、同镜头、同固件** | — | 内参差异越小 rectify 越接近纯平移 |
| M6 | **硬件同步触发**（外触发或主从触发），或至少同一时钟源 | 左右帧曝光起始时间差 **< 1 ms**；ROV 0.5 m/s 时 1 ms 对应 0.5 mm 位移 | 关键帧配对按时间戳最近邻；不同步的双目对会给出错误深度 |
| M7 | 帧上带硬件时间戳（或驱动能取到曝光时刻） | 时间戳抖动 **< 2 ms** | IMU 预积分（PREP-B-01）与双目关键帧对齐要用 |
| M8 | 全局快门优先 | 卷帘快门须给出行读出时间，且 ROV 转速受限 | 卷帘 + 转向会让特征点"倾斜"，RANSAC 刚体拟合退化 |

## 2. 强烈建议（不满足会明显缩小可用工况）

| # | 约束 | 建议值 | 原因 |
|---|---|---|---|
| S1 | 分辨率 | 1280×720 起步，1920×1080 可选 | 阶段 2 带宽账（`PREP-E-01`）按 2×720p@10 fps 1.5–3 Mbps / 2×1080p@10 fps 3–6 Mbps 算 |
| S2 | 帧率可配 | 源头（传感器/驱动）可设 5/10/15/30 fps，两路同步改 | 降帧率必须在采集源做，编码后丢帧会破坏 GOP；VO 关键帧 5 Hz（`kKeyframeIntervalS = 0.2 s`），双目 10 fps 已够，5 fps 余量小 |
| S3 | 视场角 | 水平 80–100°（水中，考虑平面窗折射后的实际值） | 与现有仿真标定（约 90° FOV 假设）一致；太窄近处重叠不足，太宽边缘畸变大 |
| S4 | 窗口 | 平面窗（非球面罩）优先；若球面罩，光心须与球心重合，误差 < 1 mm | plumb-bob 畸变模型能吸收平面窗折射，吸收不了偏心球面罩 |
| S5 | 编码/传输 | 原始或近无损（MJPEG 高质量 / H.264 低 CRF）；**编码质量 > 分辨率 > 帧率** | 教训 (b)：压缩伪影比低帧率更致命 |
| S6 | 数据接口 | USB3 或 GMSL→以太网；经伴侣计算机（树莓派 BlueOS）或独立编码器上 tether；**明确编码在哪一端** | 树莓派 USB3 带宽与 CPU 有限，2×1080p 原始流走不了；独立编码器可避开树莓派瓶颈 |
| S7 | 供电 | 与推进器电源隔离或加滤波 | 推进器电流纹波影响图像传感器噪声，也影响 HWT9053 磁航向 |
| S8 | 相机相对声呐位置 | 双目光心与声呐换能器中心的相对位置能量到 ±5 mm；建议同一刚性支架 | 声光关联（相机给方向、声呐给距离）用外参，误差直接进深度 |
| S9 | 相机相对 IMU 位置 | 同上 ±5 mm；IMU（HWT9053）与双目在同一刚体上 | IMU 预积分外参 |

## 3. 结构设计需要交付给软件侧的数据

到货前或到货时，结构侧请提供以下数字，软件侧据此填 `configs/rig/bluerov2_contract.yaml` 的 `camera_left_link`/`camera_right_link` 外参：

1. 左、右相机光心相对机体原点（`base_link`，定义见 `docs/specifications/` 坐标约定：x 前、y 左、z 上）的位置，CAD 值，单位 m，三位小数。
2. 两相机光轴相对 +x 的偏角（设计值应为 0）。
3. 云台相机（IMX462）**锁死俯仰角**（规格开放问题 3），决定 `camera_main_link` 外参。
4. 声呐换能器中心、HWT9053 IMU 中心相对 `base_link` 的位置。
5. 平面窗厚度、材料、到镜头前表面距离（用于估算水中等效焦距，标定时核对）。

## 4. 阶段 2 软件切换路径（说明为什么这些约束值得付出机械代价）

满足第 1 节约束后，软件侧切换只剩：

- rig 文件填入标定值（`stereo-acceptance.md` 第 2 步）；
- `adapters/holoocean/scenarios/blue_rov_contract_stereo.json` 已按同样的几何放置仿真双目，仿真回归先行；
- `estimator_mode` 切到阶段 2 组合模式（双目 VO + IMU 预积分 + 声呐配准并存，任一来源缺席自动降级）；
- 回环闭合前端在该模式下可开；在线辅助管线视觉侧恢复双目深度。

不满足 M2/M3/M6 中任何一条，上述路径要重新调参甚至改前端，参考教训 (a) 的代价是"ATE 从 0.67 m 到 4.32 m"。

## 5. 采购问卷（随询价单发给相机供应商）

1. 型号、传感器（型号、尺寸、全局/卷帘）、镜头焦距/视场角（空气中）、接口（USB3 / GMSL / 以太网）。
2. 是否支持外部硬件触发或主从同步？同步精度？
3. 时间戳来源（硬件曝光时刻 / 驱动收包时刻）？
4. 双目模组内置基线（若为一体式模组）：长度、出厂标定是否提供、标定文件格式。
5. 可配帧率档位；原始输出格式（MONO8 / YUV / MJPEG / H.264）；编码是否可关。
6. 水下耐压壳：平面窗 / 球面罩；耐压深度；窗厚。
7. 供电电压/功耗；线缆长度与穿舱方案。
8. 驱动支持：Linux 内核版本、是否有 V4L2 / GStreamer / ROS2 驱动；树莓派 4/5 是否有实测。
9. 预计交期。
