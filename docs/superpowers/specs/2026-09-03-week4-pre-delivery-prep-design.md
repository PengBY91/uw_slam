## 目标

第四周不再作为一个“大而全”的实现批次推进。当前唯一阻断里程碑是 PREP-B-01 的合法端到端闭环；B-02、C-03 外部导航以及依赖真实环境的 A 类任务必须遵守明确的输入契约和验收层级，不能用测试夹具或真值旁路代替完成状态。

## 完成状态的统一语义

所有第四周任务只使用以下三种完成层级：

| 状态 | 含义 | 可以声明的证据 |
|---|---|---|
| 已实现 | 代码、配置或文档已落盘，但尚未完成对应环境验证 | 文件路径、静态检查、编译结果 |
| 已本地验证 | 在当前 Linux 工作区用单元/集成测试或离线数据验证通过 | 可重复命令、测试数量、机器可读输出 |
| 已外部验证 | 在规格指定的 SITL、Windows HoloOcean、真实手柄或真实设备环境验证通过 | 运行记录、MCAP/日志、报告、操作者记录 |

“接口骨架”“dry-run”“fake transport”“场景模板”和“emitter fixture”只能达到前两级，不能替代第三方环境或真人参与的验收。

## 关键设计决定

### PREP-B-01：先纠正算法输入合同

1. 算法路径不得读取 `/gt/state`，也不得使用旧的 `RelativePoseMeasurement` 作为关键帧位姿初值。真值只进入 evaluator。
2. IMU-only 回放的关键帧边界由算法输入事件提供。第四周采用显式 `KeyframeBoundary` canonical 事件；事件只含 keyframe id、capture time 和来源，不含位姿。合成器、HoloOcean 录制器和未来在线调度器都通过同一契约发布。
3. 合成场景在首个关键帧前提供至少 0.5 s 静止预卷。静止检测成功时建立 `v0`、`bg0`、`ba0` 先验；检测失败时使用明确的宽速度先验，不把零速度写成无条件事实。
4. rig 现有 `sigma_*_bias` 和 `sigma_*_bias_walk_c` 分工固定：前者是初始偏置先验，后者是随机游走密度；禁止再跨字段回退。
5. 验收场景必须产生非零的 IMU、depth 和 sonar-range 因子；任何一种被模式分支跳过都算失败。
6. ATE ≤ 0.15 m 是无泄漏合成场景的硬门槛。求解迭代数先作为诊断项记录；在基准稳定前不再以 4–10 次作为硬门槛。
7. 测试顺序为：关键帧契约 → 静止初始化/先验 → 因子接线 → 真值隔离 → 可观测性诊断 → 无泄漏端到端。

隔离 worktree 中现有实验分支曾得到 ATE 0.0642487 m / 27 次迭代，但它使用 `/gt/state` 确定关键帧、用旧相对位姿初始化，并跳过 sonar range 因子。这个结果只作为诊断反例，不是 B-01 验收证据，补丁不得直接合入主线。

### PREP-B-02：航向观测必须有独立来源和来源证明

新增 `MagneticHeadingMeasurement`，至少携带 yaw、方差、推进器电流、capture time 和 provenance。MAVLink 侧只有在参数快照证明 EKF yaw 源为罗盘时，才可把 ArduSub 航向标记为 `ardusub_compass_ekf`；不得直接把无来源说明的 `VehicleState.attitude` 当作磁航向测量。

启用 B-02 时，C-03 参数基线固定 `EK3_SRC1_YAW=1`，禁止同时让 ExternalNav 提供 yaw，避免飞控航向经 SLAM 再回灌飞控的循环。B-02 的消息契约、残差和 builder 可独立开发；回放接线必须等 B-01 合法闭环稳定后进行。

### PREP-C-03：按周拆分

- W4：只做遥测输入，以及 `PilotCommand`、`MotionSetpoint`、`FlightModeRequest` 命令输出；SITL 是强制验收环境。
- W5：再做 `VISION_POSITION_DELTA`、参数基线、POSHOLD 和断流回落。

外部导航发送前必须通过质量门：solver converged、协方差有限且低于阈值、输出时间新鲜、目标区间 IMU 覆盖完整、关键因子没有连续拒绝。任一条件失败时立即停发，并输出结构化拒绝原因；不得重发旧增量。

### PREP-A-13：区分 fixture 与真机路径

第四周只承诺 MAVLink 的真实 SITL 路径和 IMU emitter fixture。IMU 伪装流的完整端到端验收依赖 PREP-D-03 岸上 adapter；外部时钟源与四路各 30 分钟无错仍属于后续里程碑。若 D-03 不提前，第四周产物不得称为“IMU adapter 已通过伪装流”。

### PREP-A-06/A-08/A-12

- A-06 继续按原排期推进，不能从第四周计划遗漏。
- A-08 的依赖改成 `B-06 指标/配置 API → A-08 场景与 bag → B-06 相关性验证`。真实水池尺寸未确认前只能交模板，不能声明关卡完成。
- A-12 本地可交付训练编排 harness；完整验收仍要求 A-06 场景、真实 HMI/手柄、HoloOcean，以及两名飞手各三次训练数据。

### PREP-A-09

第四周只实现原规格的 `ir_night` 和 H.264 4/6/8 Mbps 两类退化，指标限定为 Harris 角点数、匹配数和目标检测召回率。输出称为“仿真候选码率档位”；真实 IMX462 数据到达前不能给出最终码率下限。

## 计划拆分

本设计不再对应一个九任务串行实现计划，而是对应下列独立计划：

1. 第四周总控索引与状态表。
2. B-01 合法闭环收口计划（当前执行计划）。
3. B-02 消息契约与因子计划。
4. C-03 W4 遥测/命令计划。
5. C-03 W5 外部导航计划。
6. A-13 W4 emitter fixture 计划。
7. A-09 相机外观退化计划。
8. A-06 养殖区关卡续作计划。
9. A-08 受门禁约束的水池关卡计划。
10. A-12 飞手训练 harness 与外部验收计划。

当前只允许 B-01 收口计划进入代码执行。其他计划可并行完成设计，但不得绕过上面的依赖门。

## 文档与交付检查

- 主规格、设计、计划三者必须使用同一状态词和同一依赖方向。
- 每个实现计划必须列出准确文件、先失败的测试、最小实现、精确命令和预期输出。
- 当前环境无法运行的验证要写成“外部待验收”，不能写成“完成”。
- 所有完成声明前运行相应测试、`python3 tools/lint/check_layer_dependencies.py .`、traceability 检查和 `git diff --check`。
