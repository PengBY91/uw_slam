# `uw_slam` README 重构设计

## 背景与目标

根目录 README 同时服务两类读者：团队内部开发者，以及第一次访问仓库的开源用户。
重构后的文档采用渐进披露结构，让新读者在前两屏内理解项目定位、成熟度与最短运行
路径，同时保留内部开发需要的构建、测试、架构约束和高级接入信息。

本文档只规划根目录 `README.md` 的内容与组织方式，不修改代码、构建系统、子目录文档
或项目能力。

## 写作原则

- 使用中文为主，保留 C++、ROS2、MCAP、Protobuf 等通用技术名称。
- 先给结论和可执行入口，再展开背景与细节。
- 只描述代码、配置、测试或脚本能够证实的能力，不声称生产可用。
- 命令必须可复制；关键命令使用带语言标识的代码块。
- 使用静态技术与许可证徽章，不添加尚不存在的 CI 状态、在线 Demo 或性能承诺。
- 用 Mermaid 图展示数据流和依赖方向，不创建缺乏真实运行素材的截图或 GIF。
- 详细但低频的 ROS2/HoloOcean 操作保留摘要，并链接到相应子目录文档。

## 信息结构

README 按以下顺序组织：

1. 标题、项目定位、技术与许可证徽章。
2. 当前状态，明确“可运行的垂直切片”和“非生产系统”。
3. 核心能力与技术栈，让首次访问者快速判断项目范围。
4. 快速开始，以 `tools/verify_pipeline.sh` 作为首选的一键验证入口。
5. 端到端 Demo，说明 `synth_bag_gen → replay_demo`、典型输出和产物。
6. Mermaid 架构图、单向依赖和跨语言领域契约。
7. 仓库结构与各层职责。
8. 开发环境、手动构建、C++/Python 测试和 lint 命令。
9. 分层配置系统，以及 HoloOcean/ROS2 高级接入入口。
10. 开发约束与贡献流程。
11. 已知边界、许可证、移植出处和延伸阅读。

目录只列出主要章节，避免目录本身占据过多首屏空间。

## 快速路径与详细路径

首次访问者的最短路径为：安装基础依赖，运行 `tools/verify_pipeline.sh`，查看验证摘要、
轨迹和 RunManifest。手动构建与分别运行两个应用作为可调试的详细路径放在其后。

内部开发者还会获得以下明确入口：

- `tools/lint/check_no_ros_in_core.sh`：检查依赖方向不变量。
- `configs/README.md`：查看四层配置字段。
- `adapters/holoocean/README.md`：配置 Python 传感器网关。
- `adapters/ros2/README.md`：配置 ROS2 Jazzy 和 HoloOcean 消息接口。
- `NOTICE`：检查移植代码来源与许可证要求。
- `CLAUDE.md`：查看仓库内开发约定和已知工程陷阱。

## 事实校正

改写时同步修复现有 README 中已经确认的陈旧信息：

- CTest 当前注册 `14` 个测试，文档不再写成 `13/13`。
- Python 开发环境采用仓库脚本实际使用的 `venv` 与
  `pip install -e ".[dev]"` 路径，不再推荐会发生跨平台解析问题的裸 `uv sync`。
- 原先不存在的 `CODEBASE_GUIDE.md` 链接改为
  `docs/uw-slam-codebase-reference-2026-08-18.md`。
- ROS2 状态区分“节点可编译和独立启动”与“尚未连接真实 HoloOcean 数据流”。

测试数量属于时效性状态：最终 README 会写明当前验证结果，并把可重复执行的命令放在
结果之前，避免数字成为唯一可信依据。

## 验收标准

- README 中的本地相对链接全部指向存在的文件或目录。
- 所有命令与仓库脚本、CMake target 和可执行文件路径一致。
- 项目能力、未实现功能和验证范围之间没有矛盾。
- Markdown 标题层级、代码块语言和表格格式正确。
- 运行仓库现有验证流程，并以实际结果更新测试与 Demo 状态。
- Git diff 只包含 README 重构和这份设计规格，不修改 `external_repos/`。
