# `uw_slam` 文档信息架构重组设计

## 背景与目标

根目录 README 已经提供项目入口，但 `docs/` 下三份核心技术文档和
`external_repos/` 下两份顶层说明仍存在入口不足、当前事实与历史修订混排、导航
不一致等问题。本次重组让团队内部开发者能按任务快速找到权威信息，同时让 GitHub
访问者可以区分“当前实现”“目标设计”和“历史方案”。

本次只调整 Markdown 的信息组织、链接和状态说明，不改变任何架构决策、代码事实、
构建命令或项目范围。

## 适用范围

创建：

- `docs/README.md`：文档中心与推荐阅读路径。

重点重组：

- `docs/holoocean-to-acoustic-optic-slam-pipeline-2026-08-05.md`
- `docs/acoustic-optic-slam-platform-architecture-2026-08-17.md`
- `external_repos/external-repos-overview.md`

轻量增强：

- `docs/uw-slam-codebase-reference-2026-08-18.md`
- `external_repos/README.md`

不在范围内：

- `external_repos/` 下的任何第三方子仓库及其自带文档；
- `docs/superpowers/` 下的规格与执行计划；
- 代码、许可证和构建系统。`.gitignore` 只增加
  `external_repos/external-repos-overview.md` 的精确放行规则，使该顶层文档可被版本控制。

## 统一组织原则

不同类型的文档共享一组入口元素，但不复制根 README 的展示模板：

1. YAML front matter 保留文档类型、状态、创建与更新时间；缺失时只在核心长文档中补齐。
2. H1 后依次给出文档用途、适用读者、当前状态和三十秒摘要。
3. 超过约 200 行的文档提供可点击目录。
4. 用明确标签区分当前事实、目标设计、计划工作和历史背景。
5. GitHub 应能解析所有仓库内链接；Obsidian `[[...]]` 链接改为相对 Markdown 链接。
6. 低频细节保留在原专业文档，入口页只做路由，不复制正文。
7. 历史修订不再覆盖在旧结论之后让读者自行判断；重要修正整合进当前正文，审计过程
   留在有清晰标签的附录。

## 文档中心设计

`docs/README.md` 是根 README 与所有长篇技术资料之间的路由层，包含：

- 按读者角色的推荐阅读路径：首次接触、实现/调试、修改架构、配置实验、接入外部系统；
- 文档状态矩阵：文档类型、权威范围、当前/设计/历史状态、最后更新时间；
- “信息冲突时以谁为准”的优先级：代码与 schema、代码库参考、配置/适配器文档、
  长期架构、历史 Pipeline 方案；
- 文档维护约定：更新状态、验证 commit、相对链接和事实/计划边界。

根 README 的延伸阅读增加文档中心入口，但保留现有直接链接，避免增加不必要跳转。

## 各文档重组

### Pipeline 工程方案

该文档优先级最高。保留原有技术内容和审计证据，但入口改为：

1. 文档定位：第一阶段 baseline 与历史工程演进方案，不是当前代码事实的唯一来源；
2. 当前结论摘要：原串联 baseline、目标 pose-graph 架构、当前仓库实际垂直切片；
3. 状态矩阵：已实现、部分实现、尚未接通、历史方案；
4. 推荐阅读路径与目录；
5. 原有方案、接口、阶段、风险和验收正文；
6. 架构升级与代码审计修订作为明确的演进/附录部分。

正文中的 Obsidian 链接全部改为仓库内相对 Markdown 链接。若链接目标不在本仓库，
改为纯文本来源说明，而不是保留 GitHub 无法解析的链接。

### 长期架构设计

保留编号章节和 approved-design 身份，在 H1 后增加：

- 适用读者与权威范围；
- 核心决策摘要；
- 当前实现映射，明确哪些已落地、哪些仍是目标；
- 可点击目录。

第 22 节继续作为代码审计附录，但入口明确说明其修正优先于正文中的历史假设；能安全
整合的版本、接口和风险结论同步到对应正文，避免互相矛盾。现有 Obsidian 链接按与
Pipeline 文档相同的规则处理。

### 代码库参考

保留现有逐层结构和目录，只增加：

- 适用读者、“只记录代码事实”的权威范围；
- 最后核对日期和基准 commit；
- 常见任务入口，例如查类型、查 Demo 数据流、查配置、查测试和查已知边界；
- 与长期架构和 Pipeline 方案的关系说明。

不拆分该文档，也不复制根 README 的快速开始。

### 外部仓库概览

在现有正文前增加：

- 用途、只读边界和验证方式；
- 可点击目录；
- 统一总览矩阵：仓库、角色、来源、许可证、快照/可获取性、在 `uw_slam` 中的用途、
  验证范围；
- 每个详细仓库段落采用一致顺序：定位、关键目录、接口/数据流、启动参考、与
  `uw_slam` 的关系、已知限制。

现有只详细介绍 `holoocean-ros` 与 `holoocean_bridge` 的范围会在标题和摘要中说清楚，
避免让读者误以为四个仓库都有同等深度的逐文件说明。

### `external_repos/README.md`

保持短小，只把重复信息压缩成恢复清单表格，字段包括目录、clone/获取方式、许可证、
用途和已知快照。随后保留特殊说明：内部 GitLab 可访问性、`holoocean_bridge` 无公开
clone 地址、所有子仓库只读。详细分析统一链接到外部仓库概览和 `NOTICE`。

## 链接与状态治理

- 所有新增链接使用相对路径，并从链接所在文件位置计算。
- 对本仓库不存在的知识库页面不制造伪链接；保留名称并注明“外部知识库资料”。
- 长文档状态使用 `current`、`approved-design`、`evolving-plan` 或 `historical-reference`
  等清晰值，不用含义模糊的 `draft` 单独描述混合状态。
- 代码事实以当前 HEAD `919e1f0` 为初始核对基准；实施时若 HEAD 未变化，代码库参考
  记录该短 commit，否则记录实施时实际 HEAD。
- 日期使用当前工作日期 `2026-08-19`。

## 验收标准

- `docs/README.md` 能把五类常见读者任务路由到正确文档。
- 三份超过 400 行的长文档都具有用途、状态摘要和目录。
- `docs/*.md` 不再包含 GitHub 无法解析的 Obsidian `[[...]]` 链接。
- Pipeline 文档能在首屏区分当前实现、目标设计和历史 baseline。
- 外部仓库两份顶层文档职责不重复：README 负责恢复，overview 负责理解与风险。
- 所有本地 Markdown 链接指向存在的文件或有效标题锚点。
- 文档中没有新增未经代码或现有审计材料支持的能力声明。
- `external_repos/` 子仓库没有任何改动。
- `git diff --check` 通过，改动范围仅包含批准的 Markdown 文件、过程规格/计划，以及
  放行外部仓库概览所需的一条 `.gitignore` 规则。
